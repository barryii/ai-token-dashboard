# 大範圍查詢與按需明細

當前任務狀態與優先順序統一維護在[專案狀態](project-status.md)；本文保留查詢、匯出邊界和測量證據。

精確時間模式使用 `/api/time/summary`，由資料庫按完整時間範圍聚合，再回傳日、專案和小時統計。當前週期與對比週期分別計算，邊界之外和兩個週期之間的記錄不會混入結果。來源、裝置和模型維度保留在聚合結果中，頁面篩選和聚焦無需重新下載事件。

開啟精確模式的來源、模型或專案詳情時，頁面才請求 `/api/time` 的一頁事件，每頁 50 條，按時間升序。下一頁使用游標，上一頁儲存游標而非整頁資料。關閉詳情、切換篩選或重新整理後會取消舊請求並重置分頁。列表中的統計和排序始終基於完整範圍的聚合資料，不會隨事件翻頁改變。

`/api/time` 支援重複的 `source`、`device`、`model` 和 `project` 查詢參數。游標綁定時間範圍和篩選條件；修改條件後必須從第一頁開始。MySQL 使用區分大小寫的事件、模型和專案身份比較，避免大小寫不同的專案被合併。

費用直接彙總已存金額。快取節省估算沿用現有非階梯定價，並在每個事件上先將負值截為零，再求和；不能對日彙總只截一次，否則快取寫入較多的事件會抵消其他事件的節省。專案彙總同時保留完整的 reasoning token 數。

普通日彙總與精確明細匯出使用 `/api/export.csv`，伺服器端在同一唯讀快照內每批讀取 1,000 行並寫入暫時 CSV，釋放資料庫交易後再串流下載。瀏覽器直接管理下載，頁面不累積全部明細。下載進度、失敗和取消在瀏覽器下載列表檢視；準備期間取消後停止後續分頁並清理暫時檔案。趨勢匯出仍是當前圖表的小型記憶體匯出。

## 普通日期模式與複盤

頁面啟動先讀取受相同驗證保護的 `/api/config`，篩選、明細時間、額度絕對時間和複盤週期統一使用伺服器端 `DISPLAY_TZ`。無設定時沿用伺服器端主機時區；用戶端不自行採用瀏覽器時區。日期型輸入保持日曆日期，精確輸入在顯示時區轉換成 UTC 後供統計、對比和 CSV 共用。日光節約時間不存在的時段拒絕查詢，重複小時使用較早的時刻；直接 API 請求可用明確 UTC 偏移選擇另一個時刻。已有日彙總不會因顯示時區改變而重建，採集端與中心仍應設定一致的時區。

普通看板通過 `/api/data?startDate=...&endDate=...` 讀取所選日期；開啟對比時，查詢範圍同時涵蓋等長的上一週期。複盤頁按當前週期和它的對比週期請求資料，例如本月同時包含上月，上月同時包含上上月。只有選擇「全部」才載入全部歷史日彙總和專案彙總。裝置、來源、模型篩選仍在已取回的日期範圍內完成，切換這些維度不額外請求。

日介面新增全域 `dateRange`、`dimensions` 中繼資料，保留全域 `eventRange`；它們不隨請求日期縮小。因此選中沒有資料的日期後，仍可選擇其他歷史裝置、模型或全部歷史。原有不帶參數的介面保持相容。

熱力圖只請求所選日期最後 28 天的 `/api/hourly?startDate=...&endDate=...`，與頁面實際顯示範圍一致。伺服器端先用寬於任何時區偏移的 UTC 範圍限定索引掃描，再按 `DISPLAY_TZ` 的本地日期過濾、聚合。不能直接使用已存 `usage_date` 替代顯示時區，否則跨午夜和時區設定變化的舊記錄可能漏掉。MySQL 的篩選維度保留大小寫區別。

伺服器端小時查詢共享進行中的請求，並快取最多 4 個結果、每個最多 5,000 行、有效期 10 秒。快取鍵包含時區、日期範圍和資料庫來源修訂號，因此其他升級後的採集/同步行程提交變化後會立即失效；繞過專案寫入入口的手工 SQL 只能靠到期重新整理。額度查詢也共享進行中的請求，成功結果快取 60 秒、上游錯誤快取 10 秒；憑據和回應不持久化到快取檔案。

2026-10-03，在含 83,419 條事件的獨立 SQLite 副本上請求 2026-09-02 至 2026-09-29 的小時統計，首次 208 ms，隨後三次為 2/1/1 ms；381 行、70,098 位元組回應逐字一致。計時包含 HTTP 與 JSON 讀取，不含瀏覽器繪圖；隔離服務沒有定價快照，這不是資料庫掃描本身提速或所有環境的效能保證。

## 頁面資源與瀏覽器迴歸

首頁與複盤分別按路由載入，圖表仍按可見區域載入。靜態服務支援 gzip、ETag 條件請求和 HEAD；帶建置雜湊的資源使用私有長期快取，HTML 每次重新驗證。所有快取判斷之前仍執行存取認證。部署時需同步發布 HTML 和建置資源，頁面資源失敗會顯示重新載入入口。

`npm run test:browser` 使用 Playwright Chromium、固定時鐘、UTC 瀏覽器和 Asia/Shanghai 暫時伺服器端，驗證時區邊界、設定失敗重試、遲到請求、精確統計、明細分頁與重試、CSV、行動版面、複盤和圖表還原。首次執行先執行 `npx playwright install chromium`（Linux 可加 `--with-deps`）；測試不使用個人日誌或額度憑據。CI 在獨立 Ubuntu job 執行。

每個頁面、每類查詢分別有 30 秒記憶體快取，最多 4 個範圍，每個結果最多快取 5,000 條陣列記錄；大範圍仍可查詢，只是不進入快取。快取不持久化、不跨頁面共享；重新整理或本機採集完成會清空看板快取。外部裝置同步的變化可透過重新整理獲得，切換範圍時也會重新讀取已過期快取，不新增背景輪詢。切換日期時取消舊請求；遲到回應、失敗或取消的請求不寫入快取。新範圍未載入完或失敗時顯示載入/重試狀態，不把上一範圍的資料作為新範圍顯示或匯出。

## 精確時間模式本機驗證

2026-09-26，使用同一份本地資料庫副本的 80,995 條事件，範圍為 2026-04-01 至 2026-09-27，交替比較完整事件分頁讀取與聚合讀取，共 3 輪。比較包含 HTTP 回應讀取與 JSON 解析，不包含瀏覽器繪圖；兩種路徑均未啟用回應壓縮。

| 指標 | 完整事件分頁 | 聚合統計 |
| --- | ---: | ---: |
| HTTP 請求 | 41 | 1 |
| 回應大小 | 62,165,147 位元組 | 1,359,983 位元組 |
| 本機耗時中位數 | 454 ms | 483 ms |

本輪主要減少約 97.8% 的傳輸體積和瀏覽器中的事件物件數量；不將其描述為資料庫查詢耗時下降。資料庫仍需掃描所選範圍內的事件完成聚合。Token 各分項、已存費用、快取節省估算逐項比對一致（浮點容差 `1e-7`）；瀏覽器驗證了精確日期篩選、對比週期、詳情上一頁/下一頁和完整統計保持不變。

自動測試涵蓋超出第一頁的 2,505 條事件、邊界和空範圍、對比週期、專案及多維度篩選、游標隔離、每事件快取節省截斷、HTTP 驗證；PostgreSQL/MySQL 的聚合和分頁由 CI 的真實資料庫服務驗證。

## 大範圍查詢的可重複基準

`npm run benchmark:query -- 100000`（或 `1000000`）只建立合成 SQLite：365 天、2 個裝置、2 個來源、3 個模型、4 個專案。每個情境用三個新 Node 行程，避免建庫記憶體計入查詢峰值；作業系統檔案快取未清空，因此不是冷盤基準。腳本檢查日/專案彙總 Token、金額及選定範圍與產生資料一致，並在結束後刪除暫時資料庫。

2026-10-04，macOS arm64、Node 22.22.2；時間取三次中位數，峰值 RSS 取三次最大值。計時含 `queryDaily`、全域中繼資料及 JSON 序列化，不含 HTTP、瀏覽器繪圖、小時統計或真實價格匹配；合成模型沒有價格，金額來自已存值。新行程查詢前 RSS 約 49 MiB。

| 事件數 / 範圍 | 日 / 專案日彙總行 | 回應位元組 | 查詢及序列化 | 行程峰值 RSS |
| --- | ---: | ---: | ---: | ---: |
| 10 萬 / 全部 | 4,380 / 17,520 | 10,664,883 | 159 ms | 157 MiB |
| 10 萬 / 30 天 | 360 / 1,440 | 876,853 | 19 ms | 63 MiB |
| 100 萬 / 全部 | 4,380 / 17,520 | 10,755,643 | 1,090 ms | 158 MiB |
| 100 萬 / 30 天 | 360 / 1,440 | 884,213 | 190 ms | 63 MiB |

這個固定維度樣本中，事件數增加十倍主要增加資料庫掃描/分組時間；回應大小和查詢記憶體沒有同步增加，但全量回應已經約 10 MiB。僅加實體化彙總不能減少回傳的日/專案維度，也不能解決瀏覽器載入全部歷史的成本。因此本輪保留現有日期查詢與分頁，不新增彙總表。若實際實例頻繁查詢百萬級全歷史，下一步應同時測量瀏覽器記憶體、服務並行和遠端資料庫，再決定伺服器端維度篩選/聚合與實體化彙總；此處不宣稱 QUERY-02 已完成預聚合。

## CSV 匯出邊界

- 匯出遵循當前日期/時間、來源（包括聚焦來源）、裝置和模型篩選，不包含上一週期對比資料；費用直接取已有記錄，不重新估價。
- 日彙總與事件使用穩定複合鍵分頁，支援超過單頁的資料；欄位含逗號、雙引號或換行時進行 CSV 轉義，可能被試算表解釋為公式的文字加單引號前綴。
- 重複使用看板驗證，伺服器端回傳附件並停用快取。完成準備後才傳送回應標頭和準確的 Content-Length；準備失敗不會偽裝成成功下載，傳輸失敗會斷開下載。
- SQLite 在獨立唯讀連線中建立快照；PostgreSQL 使用唯讀可重複讀交易；MySQL 明確指定可重複讀和一致性快照，遵循[官方交易契約](https://dev.mysql.com/doc/refman/8.4/en/commit.html)。並行插入、更新、刪除或改寫分頁鍵不改變本次快照中的結果。
- CSV 在作業系統暫時目錄中以隨機私有目錄和檔案產生（POSIX 目錄 0700、檔案 0600）。每次僅持有一頁資料；需要約等於 CSV 大小的暫時磁碟空間，並增加下載開始前的準備時間。下載開始前釋放資料庫交易，慢用戶端只佔用檔案串流。
- 正常完成、取消和失敗均關閉控制代碼並刪除暫時目錄；取消在當前資料庫查詢或檔案寫入回傳後生效。行程被強制終止時無法執行 finally，遺留私有檔案需由系統暫時目錄清理策略處理。本輪不新增跨行程清理器。
- 首頁已移除歷史彙總口徑提示橫幅；費用和專案歸屬說明仍保留在幫助文件，資料核對欄位及歷史費用保留策略未改變。
